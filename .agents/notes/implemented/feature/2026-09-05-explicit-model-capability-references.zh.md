# Agent Note: Explicit built-in model capability references

Status: implemented

[English](2026-09-05-explicit-model-capability-references.md) | 中文

## Problem

pi-ai 模型条目把请求身份与能力元数据放在一起。自定义网关可以使用不同的模型 id，却支持与已安装模型相同的上下文容量、输入模态、推理等级和协议兼容性。若要求用户把每个能力字段复制到网关 profile，配置会重复目录数据，设置页面也无法直接提供现有的思考等级选项。根据相同模型 id 推断来源并不可靠，因为 id 不能证明提供方、协议、端点或能力相同。

## Decision

`PiAiModelProfile.capabilitiesFrom` 明确指定一个内置 pi-ai 提供方和模型。路由解析使用该目录条目的显示名称、输入模态、上下文容量、输出容量、推理标志和 thinking 等级映射；只有引用模型的 API 与路由模型解析出的 API 一致时，其兼容元数据才可复用。已配置条目的显式字段优先于引用；未知的内置提供方/模型组合会让 profile 解析失败。

该引用只提供元数据。已配置路由继续使用自己的 provider key、模型 id、API、端点、成本、凭据和提供方认证。能力解析不会把来源提供方的身份或端点复制到自定义路由。协议存在差异时，仍通过路由级或模型级 `compat` 明确描述。

Models 设置编辑器为该引用提供两个级联下拉框。提供方下拉框只列出内置 pi-ai 提供方，模型下拉框列出所选提供方的已安装模型；更换提供方会清除旧模型，不执行模型 id 自动识别。只有两个选择都存在时，编辑器才序列化 `capabilitiesFrom`。

## Testing

目录测试覆盖显式能力继承、显式字段优先、路由身份保持、按 API 匹配的兼容继承、未知引用，以及没有引用的旧 profile 行为不变。客户端测试覆盖仅显示内置提供方、不自动匹配、更换提供方时清除旧值、完整序列化，以及从既有提供方编辑器和新增自定义提供方卡片保存引用。完整仓库类型检查与 LLM/客户端聚焦 Vitest 均通过。

## Alternatives considered

**根据相同模型 id 自动推断来源。** 否决：相同 id 不能证明两个提供方暴露相同能力或协议，静默匹配还会让拼写错误与有意路由无法区分。

**复制来源提供方、API、端点或认证设置。** 否决：请求身份属于用户配置的自定义路由。复制这些字段会让请求发送到内置提供方，或使用其认证，而不是用户选择的网关。

**要求用户重复填写全部能力字段。** 否决：这会把已安装目录数据重新写入用户设置，用户必须正确复制后才能使用推理等级，pi-ai 目录变化时也会产生漂移。

## Consequences

自定义路由可以复用内置能力元数据，同时保持发送给 pi-ai 的 provider 和模型身份不变。引用受已安装 pi-ai 目录版本约束：内置提供方或模型被移除、改名后，必须更新显式引用才能恢复可服务状态。网关特有的协议行为仍需显式设置路由级或模型级兼容选项；UI 也明确不提供自定义来源或自动匹配路径。
