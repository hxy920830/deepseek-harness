# Agent Note：桌面端 Session 日志保存位置与终态成功弹窗

状态：implemented

[English](2026-08-23-desktop-session-log-save-location.md) | 中文

## 问题

在 Tauri 桌面壳中，Session 导出弹窗自身永远无法到达终态：锚点点击后，弹窗会一直显示成功文案，直到用户手动关闭；归档也总是落在 WebView 的平台下载目录，无法选择目标位置。导出流程需要：(1) 通用设置中的默认下载目录控件和原生文件夹选择器；(2) 一个报告完成、提供文件管理器操作并能自行关闭的成功弹窗。

## 决策

`@deepseek-ai/dsh-client-ui-desktop` 拥有新偏好与原生能力。其 Host 设置命名空间新增 `sessionLogDir`（空字符串 = 平台默认），第二个 `settings.general.item` 行渲染当前目录和一个文件夹图标按钮——通过 `rfd` 打开原生选择器并经既有设置作用域持久化。插件发布可选的 `desktopSessionFiles` ctx 服务（目录查询、不覆盖保存、文件管理器定位、默认程序打开），消费者保持与 Tauri 无关，在普通浏览器中视为能力缺失。

Rust 在执行操作处强制安全形态：每个命令只接受“目录 + 文件名”对，校验文件名符合 `dsh-session-<id>.zip` 约定且目录为已存在的绝对路径；保存遇到冲突时唯一化命名（`name (1).zip`）而不覆盖。渲染进程从不传入自由文件系统路径；定位与打开会把先前返回的绝对路径拆开并重新校验两半。

`@deepseek-ai/dsh-session-log-export` 在每次手势时惰性消费该服务（`ctx.get('desktopSessionFiles')`），运行时 `inject` 列表因此不包含包名——注入等待的是服务。配置了目录时，控制器把 ZIP 取回一次并原生保存，在 `SessionLogDownloadEntry.filePath` 中发布绝对路径；否则维持原有锚点点击的浏览器路径。成功现在是终态：原生保存显示「Session 导出成功」以及打开文件夹 / 打开文件 / 关闭三个按钮，六秒后自动关闭；浏览器下载保留两秒短暂提示。失败仍需显式关闭。

session-log-export 对 ui-desktop 的类型依赖经由环境 `Context` 扩充和 peer dependency 传递；没有 slot 或值导入跨越边界。

## 已考虑的替代方案

**复用 tauri-plugin-dialog 做选择器。** 否决：只需要文件夹选择；把 `rfd` 包进自有命令可以避开插件注册、JS API 包和 ACL 条目，同时仍使用维护中的对话框实现。

**让 Rust 记住目录。** 否决：Host 设置文档已经是 Web UI 共享的唯一偏好所有者；在 Tauri 进程里复制状态还需要自己的持久化与迁移方案。

**成功后立即自动关闭。** 否决：用户要求可见的完成反馈和可操作按钮；短暂展示窗口既保留确认感，又无需手动关闭即可让流程回到静默。

## 后果

桌面端导出落入所选文件夹且名称不会冲突覆盖；无论用户是否点击，成功弹窗都会自行终结。服务或目录缺失时浏览器行为不变。归档字节目前以 JSON 数字数组跨 IPC，超大导出需要支付编码开销——已记为已知限制而非提前优化。下载开始后的失败上报按路径区分：浏览器路径由下载管理器报告，原生保存路径由弹窗错误状态报告。
